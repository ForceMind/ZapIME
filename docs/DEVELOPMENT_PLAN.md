## 0. 项目使命与成功定义

**一句话定位：一个输入法，连接所有设备；输入习惯、词库、短语和收藏的数据归用户掌控。**

目标是让 Android、iOS、macOS、Windows 使用同一套 ZapIME 品牌和用户数据体系，保留四端原生输入法集成能力，共享成熟的中文输入引擎，实现可靠的跨设备同步、自定义候选字词、云剪贴板和可离线恢复的数据。用户不必依赖某个第三方输入法运营者的服务器能长期存在。

这不是做一个网页键盘，也不是修改三星原生键盘或其它第三方输入法：四端均须以各自操作系统认可的**真实系统输入法**运行。

### 必须同时满足的验收结果

1. **真正四端输入**：Android 的 InputMethodService、iOS 的键盘扩展、macOS 的 InputMethodKit、Windows 的 TSF 均能在真实应用中输入、上屏、删除、移动光标、选词；有至少一套可安装/可运行的验证产物。
2. **同一套可迁移数据**：四端个人词库、自定义候选、快捷短语、永久收藏采用统一数据契约，数据同步与设备迁移有明确冲突策略。
3. **完全断网仍能输入**：本地引擎和已同步数据不依赖云端；服务器不可用时不能阻塞按键、候选展示与文本上屏。
4. **数据可独立恢复**：用户可从客户端导出受版本管理的标准归档，在新服务器和新设备上恢复；必须实际演练，不能只验证“备份成功”。
5. **云剪贴板可自建**：按需上传、端到端加密、多设备批准、搜索、插入、删除、置顶、保留期；官方云服务不是必需条件。
6. **品牌与许可合规**：ZapIME 使用自身品牌与包标识；复用 GPL 源码须保留上游许可、版权、NOTICE 和来源追溯；不把缺少明确授权的后端源码擅自当成可复用源码。
7. **私有源码与可交付**：保持本仓库 Private；签名凭据、账号密钥不提交仓库；可审计的提交、CI、构建说明、测试记录齐备。若向外分发含 GPL 代码的程序，依许可向接收者提供对应源码；Private 仓库本身不能替代该义务。

## 3. 数据产品：五个分开的空间

1. **个人词库 PersonalDictionary**：字/词/拼音编码、输入方案、词频权重、用户选择学习结果、删除记录；基础转换词库与个人数据分开。
2. **候选规则 CandidateRules**：对特定编码、输入方案和上下文范围设定置顶、排序、过滤及例外；规则应用顺序为：用户强制规则 > 精确个人词库 > 原引擎有信任证据的命中 > 模型仅在可比的备选候选中重排。不要把 LLM 的打分当作绝对答案。
3. **快捷短语 Snippets**：编码/触发词、正文、标签、排序、收藏、是否允许跨设备同步；可以先只做静态文本，动态变量以显式、可预览、无外部副作用方式新增。
4. **云剪贴板 CloudClipboard**：**临时交换区**，用户明确上传，密文保存，可设到期与条数上限（第一版可沿用 50 条），默认不承担永久保存职责。
5. **永久收藏 Vault/Favorites**：**不会被剪贴板自动清理**的内容；从剪贴板或短语显式保存；保留版本、搜索、可加密导出，容量与分层配额单独管理。

输入法设置 Preferences、设备身份与授权 Devices、同步变更日志 Operations、密钥与备份 Recovery 是横向基础数据，不应混为剪贴板历史。

### 统一数据契约（实现时固化 schema 和 migrations）

- 每个实体有稳定 UUID、所属用户、类型、schema_version、修订号、软删除 tombstone、修改来源 device_id 和时间戳（时间戳只做展示/辅助，不能单独决定冲突胜负）。
- 词库唯一性/重复约束由“方案+标准化编码+词条+范围”决定；相同正文但不同编码不能错误去重。
- 候选置顶和优先级是用户显式规则，不因上游引擎升级被意外覆盖。
- 同步使用 client_operation_id 幂等、服务端单调 revision/cursor、增量拉取和离线待发送队列；断线重试不重复上屏、不重复创建词条。
- 删除传播 tombstone 并有合理保留窗口，防止长期离线设备重新上传被删除条目。
- 双设备冲突：不同记录合并；同一记录按修订/因果及字段级策略决定，冲突无法自动解决时保留双方版本并提供用户选择；不用最后写入的本机时间简单覆盖。
- 设备本地设置与全局共享设置显式区分：键盘高度、物理键盘快捷键、平台能力限制不能被错误从手机推送到电脑。
- 编辑时立刻写本地数据库；后台异步同步。启动和联网不应该卡住键盘主线程。

## 4. 推荐技术架构

**采用 MSIME 共享 Rust 输入核心 + 四端原生宿主 + ZapIME 自建同步服务的单仓方案。**

建议在尽量保持上游目录结构的前提下演进：

- platforms/android：Android InputMethodService、原生设置、ClipboardManager/Keystore 适配。
- platforms/ios：原生设置 App + UIInputViewController 键盘扩展、App Group、Keychain、Swift 适配。系统对 secure text field、权限和扩展进程有限制。
- platforms/macos：InputMethodKit 宿主、安装/签名、Keychain。
- platforms/windows：TSF 宿主、注册/卸载、系统安全凭据存储（DPAPI 等）。
- crates/engine、crates/input-runtime、crates/host-api：保留并验证共享 Rust 输入状态、跨平台 FFI、候选会话与选择代次。
- crates/zapime-data（拟新增）：共享可验证数据模型、导入导出、冲突合并、变更日志、敏感字段过滤。
- crates/zapime-crypto（拟新增）：端到端加密和跨设备密钥封装；如直接复用有明确许可证的上游协议实现，要严格标注来源和版本。
- services/sync（拟新增）：独立授权实现的 Go/Rust HTTPS API（优先 Go + PostgreSQL），用户/设备/变更/备份服务；不强制与上游服务器兼容所有社区和非核心功能。
- services/relay（拟新增/复用合法部分）：云剪贴板中继，与同步服务器可共用部署但逻辑与存储分域。
- docs：产品规则、架构、协议、隐私、许可、操作手册、灾难恢复和测试报告。
- scripts、.github/workflows：构建、静态检查、资源来源核验、四端 CI。

优先保留上游成熟宿主的系统集成代码和输入逻辑，不应为统一界面而把所有端改成 WebView。共用**业务数据与模型**，不是强制共用所有 UI 控件。

核心架构图：

    Android IME   iOS Keyboard   macOS IMK   Windows TSF
          \            |              |             /
           \           |              |            /
            ---- Rust Engine + Input Runtime + Host API ---
                            |
                   Local DB + Personal Rules
                            |
                 Async Sync Client + E2EE
                            |
                   HTTPS Self-hosted API
                            |
                  PostgreSQL / Ciphertext
                            |
               Encrypted Backup + Restore Kit

域名规划（仅在确认购得并控制域名之后启用）：zapime.com 官网、sync.zapime.com API、可选 app.zapime.com 管理入口。未持有域名时使用经过认证的临时部署地址，任何假定 URL 不写死到发布版。

## 5. 云剪贴板与平台边界

### Android
- 在 ZapIME 为当前默认输入法且开启本机剪贴板历史时，可按系统允许的方式监听普通文本复制；排除已知敏感来源、密码与不允许学习的字段。
- **默认不自动上传到云**；“发到云端”必须显式操作。可以提供用户自主开启的自动同步试验项，但必须明确边界、可按应用排除，并完成隐私与系统兼容审查。
- 本机剪贴板历史不无限增长；永久保存须通过收藏动作。

### iOS
- 采用真实第三方键盘扩展，部分敏感输入框系统会切换到系统键盘；不能承诺对每个 App 或每次复制都保持持续后台监听。
- 网络同步受“允许完全访问”等系统要求约束；不默认要求与必要功能无关的敏感权限。
- 剪贴板读取/保存以用户明确点击系统允许的粘贴操作或主 App 的保存动作实现；不承诺静默捕获全系统复制。
- 同步时机以进入 App、打开剪贴板面板、键盘可用时合规刷新为主；不能依赖键盘后台常驻或实时 WebSocket。
- 提前验证键盘内存、签名、App Group 和真机可用性。

### macOS / Windows
- 可在各自许可权限下提供更强的桌面剪贴板快捷操作，但自动云上传仍默认关闭。
- 处理目标窗口切换/失焦、原生输入法注册、TSF/IMK 生命周期和受保护字段。剪贴板插入与剪贴板复制须明确区分，不能误向错误窗口提交。

## 6. 安全、隐私与密钥恢复

- **离线输入为默认值**：除用户明确开启的同步、更新检查等用途外，不发送输入流、候选、剪贴板及个人词库到第三方服务器；所有网络请求有明确数据流说明和退出开关。
- 使用 TLS，设备令牌有范围与过期策略；密钥存 Android Keystore、Apple Keychain、Windows 受保护存储等，不写入 Git、日志或崩溃报告。
- 剪贴板正文、个人短语/词库/永久收藏等个人文本采用端到端加密；服务端只保存密文与最小元数据，搜索在客户端本地完成。加密算法应复用经过审计的库和明确版本化的协议，不设计自创密码学。
- 新设备申请必须由已授权设备批准，显示双方核对码；支持撤销、轮换、设备丢失/重置。
- **不能假设“云端密文备份等于可恢复”**。设计用户持有的加密恢复包与恢复密语/恢复码；在仍有旧设备时可迁移密钥；全设备丢失但保存了恢复包/恢复码时可以恢复。用户同时丢失所有密钥、恢复包及恢复码时，应明确告知 E2EE 数据不可恢复，不要制造后门。
- 密钥轮换、密码学版本更新、误删撤销、归档损坏都应有测试。
- 个人数据采用三重保障：每端的本地副本 + 用户可下载的加密标准归档 + 服务端分离存储的加密数据库备份；实行 3-2-1 原则并定期演练。服务端备份不能替代用户的 E2EE 恢复资料。
- 系统密码字段、验证码、私密模式与不允许个性化学习的输入不进入学习/云剪贴板/遥测，拒绝默认键盘全文日志。
- 同步事件和安全审计日志不包含明文输入；异常数据、过大请求、恶意模型/词库/插件输入做边界校验与限流。
- 单独维护 SECURITY.md、PRIVACY.md、THREAT_MODEL.md 和 SECURITY_TEST_REPORT.md。

## 7. 备份与迁移契约

用户可以分别导出：
- **个人数据 ZIP**：manifest（格式、版本、校验和）、settings、dictionary、candidate-rules、snippets、favorites、可选的本地剪贴板历史与学习状态；不包含未经同意的密码、服务 token。
- **加密完整恢复包**：包含恢复上述 E2EE 内容所需、由用户恢复密语保护的恢复材料；不能明文存根密钥。
- **可读开放格式**：自定义词库 TSV/JSON，短语 JSON/CSV，收藏 JSON/Markdown/CSV（用户主动选择明文导出时明确提醒）。

恢复必须做到：全新安装 -> 新建空同步服务 -> 导入恢复包 -> 恢复密钥 -> 重建四端同步 -> 逐条抽样校验。规定校验和、格式版本、兼容性、全程原子性/回滚或可恢复的分段导入；不得出现 UI 显示成功、数据实际未恢复。

现有不同输入法（三星、搜狗、微信输入法、微软拼音等）迁移以**它们实际允许的导出接口**为前提。没有公开导出途径时提供手工导入、自定义词表和短语录入，不宣称能读取其他输入法的私有数据库，也不通过 root/越狱进行默认迁移。

## 9. 实施路线图：依赖有序，不以固定天数或章节式轮次为界

### M0 — 上游与本仓审计（开始工作的第一关）
- 重新查 ForceMind/ZapIME 最新提交、README、权限、分支；建立状态基线。
- 对 MSIME、chinese-ime-lm、msime-cloud 进行源码结构、活跃分支、子模块、第三方词库、构建门槛、许可证及 copyright/NOTICE 清点。
- 明确可合法移植的部分、不可直接复制的服务端部分、需要独立实现或另行授权的部分；冻结上游 commit、记录 SHA、搭建源代码来源记录和第三方组件台账。
- 确认四端宿主的当前编译链和构建依赖；优先做最小证明，不先重做所有 UI。
- 产物：docs/UPSTREAM_AUDIT.md、docs/ARCHITECTURE.md、docs/LICENSE_AUDIT.md、docs/REQUIREMENTS.md、docs/STATUS.md、AGENTS.md、M0 跟踪 Issue。
- 门禁：未知许可未被越界复制；仓库内没有密钥；计划与实际状态一致。

### M1 — 可编译的共享核心与四端原生“能输入”
- 在适当的许可基础上引入/重构共享 Rust 核心，保留上游版权与许可；保留 Git 来源记录。
- 各平台建立 ZapIME 独立包 ID / Bundle ID / TSF 注册名及隔离用户目录；不要与 MSIME 数据或注册项冲突。
- Android：优先完成可安装 APK、真实弹出键盘、中文/英文输入、选词、退格、应用切换。
- **尽早并行做 iOS、macOS、Windows 最小宿主编译与输入冒烟**，在架构早期暴露 iOS 签名/权限和 Windows TSF 的真实限制，不把 iOS 推迟到所有高级功能之后。
- 建立 CI、源代码构建说明、Android APK 与桌面/Apple 调试产物的生成流程。
- 门禁：四端至少各有一次明确记录的构建/输入结果；受签名或设备限制的未通过项必须标为阻塞，不能写成已完成，继续推进其余可行工作。

### M2 — 本地数据与用户候选闭环
- 落地统一 Data Schema、SQLite/平台本地存储、个人词库编辑、固定排序候选、快捷短语、永久收藏及本地剪贴板面板。
- 实现候选规则优先级、索引更新、离线写入队列和版本化导入导出。
- 完成输入主线程无网络依赖、对恶意词条与大词库边界的校验。
- 门禁：四端断网输入可用，用户自定义词条/短语生效，导出新装可恢复，输入引擎回归无显著退化。

### M3 — 自建同步服务与 E2EE
- 确定后端是“依法获得授权复用”还是“独立实现兼容核心协议”；无许可不复制 msime-cloud 代码。
- 实现 HTTPS 服务、PostgreSQL schema/migrations、登录/设备、变更 API、幂等增量同步、服务端加密元数据与密文存储。
- 实现端到端加密的剪贴板/收藏/短语/词库数据，以及设备配对与撤销。
- Docker Compose 单机可部署、反向代理 TLS、服务诊断、数据库备份和回滚脚本；把实际服务器地址做成安全可配置项。
- 门禁：两台模拟客户端可以离线编辑、并发同步、撤销设备；服务管理员无法从数据库读到正文；服务器中断不影响输入。

### M4 — 四端同步闭环与真实设备验证
- 四端接同一服务、支持配对、同步词库/候选规则/短语/收藏、云剪贴板显式发送与键盘内插入。
- 统一相同账号的设备列表和版本冲突；同步请求主线程隔离，iOS 按前台可用时机执行。
- 进行 Android ↔ Windows、Android ↔ macOS、iOS ↔ 其他三端、四端轮转的真实互通实验。
- 门禁：A 端新增短语后 B/C/D 同步可用；双端离线不同修改不丢失；撤销设备后不能再读取更新；云端清空后仍可从合法本地加密备份恢复。

### M5 — 完整备份恢复与统一 UI/UX
- 完善恢复包、恢复码/密语及全新服务器迁移路径；验证“全部设备丢失但保留恢复材料”的灾备场景。
- UI 重设计：ZapIME 自主品牌、触屏候选与工具栏、剪贴板收藏页、云状态、设备授权、可见的同步错误、备份入口、支持大字号/暗色。
- 安全与隐私提示：云上传默认关闭，任何导出明文、授权新设备、清空云端操作均有清晰确认。
- 门禁：用户无需读技术文档就能开箱输入、配置设备、迁移个人数据；四端 UI 含义一致但尊重各自原生体验。

### M6 — 测试、发布工程与持续维护
- 完成跨平台 CI、单元/集成/E2E、威胁模型复核、许可审计、依赖漏洞扫描、性能回归、二进制签名及发布物校验。
- Android 签名 APK、iOS Xcode/TestFlight 或正式分发、macOS 签名/公证、Windows 安装程序与卸载数据保留策略按可用身份分别落实。
- 建立版本号、Changelog、用户手册、管理员备份手册、升级/回滚、迁移脚本和回归测试；根据实际覆盖范围宣告 Beta/Stable，绝不把“编译成功”表述为“已正式发布”。
- 门禁：完成第 0 节所有必需验收，已知限制如实公示。

## 10. 关键风险和决策闸门

| 风险 | 应对策略 |
| --- | --- |
| MSIME 为 GPL-3.0-only，含多种第三方许可 | 保留合规的源码/版权/许可证，单独维护 SPDX 清单；若未来需闭源商业发行，重新评估独立实现，绝不直接删除署名 |
| msime-cloud 公开但授权不明确 | 先核实 LICENSE / 文件头 / 作者许可；未获授权仅借鉴公开协议并独立写服务端 |
| iOS 第三方键盘无法任意后台读剪贴板 | 产品定义为显式保存、打开时刷新、主 App 辅助，不承诺系统不允许的自动化 |
| 服务器倒闭导致数据丢失 | 本地优先、客户端可读导出、用户持有密钥恢复包、异地备份、灾备演练 |
| E2EE 设备全丢导致密文不可解 | 提供并验证恢复密语/恢复包；不可恢复情形必须事先明示 |
| 上游更新快，与改名定制发生冲突 | 固定上游 SHA，建立变更记录；核心尽量低侵入，独立扩展模块；定期人工审核合并 |
| 迁移其他输入法历史难以获得 | 仅支持其他输入法允许的导出/导入路径，不依赖破解私有数据库 |
| 过度追求全功能导致无法交付 | 先四端最小可输入，再本地个性化与独立同步，AI/社区/复杂皮肤后置 |
| 域名和商标不确定 | 未购买域名时不绑定生产依赖；公开发行前另行核查商标、应用名称 |
| 缺少苹果证书/Windows 环境或本机权限 | 能构建先构建、模拟器先测；明确客观阻塞，不伪造签名与真机报告 |

## 13. 不变的产品判断

- **ZapIME 不修改三星原生输入法**，而是独立安装、由用户选为默认输入法。
- **四个平台输入法实现可以不同，但用户的词库、候选、自定义短语和永久收藏必须相通。**
- **临时剪贴板不等于永久收藏**；服务器运行不等于数据安全；E2EE 不等于自动可恢复。
- **核心体验永远可以脱离网络运行；云端由用户掌控，并有可迁移的数据和加密恢复能力。**
- **保持成熟、中性、可维护的技术文档，不加入无意义的个人维护者宣传。**

本计划为工程主线，后续只在经过验证并记录决定后更新，不得把尚未实现的目标误写成现状。
