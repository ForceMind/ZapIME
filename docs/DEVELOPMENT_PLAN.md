## 1. 产品目标与最新决定

**一个输入法，连接所有设备；输入和个人数据不依赖某一家服务商长期存在。**

ZapIME 是 Android、iOS、macOS、Windows 的真正原生中文输入法，而不是 VoiceKey 的重新贴牌，也不是只给其他输入法外挂语音。长期提供统一的个人词库、自定义候选、快捷短语、永久收藏、显式保存的剪贴板、可恢复备份，以及用户可自建的端到端加密同步。

本轮新增的明确目标是：**优先交付可以给用户及 VoiceKey 作者试用的 Android 双离线引擎 Alpha。** 在同一个 ZapIME 键盘中，用户能够选择 X-ASR 或 VoiceKey 微信离线，完成模型准备、按键发起录音、实时预览、停止、确认插入、取消及重录。不要等四端、云同步和英语伴学全部完成才交付 Android。

用户已明确确认 VoiceKey 作者同意本项目使用和整合其源码。按此授权前提继续工程，不反复向用户询问同一授权。保留作者署名及来源，整理授权记录；第三方模型、厂商服务及专有二进制的权限另行核验，不能由朋友源码授权自动推导。

## 2. 不变的产品边界

- 默认离线、本地优先；正常输入、已安装语音模型、个人资料搜索不等待网络。录音、识别正文和编辑器上下文不自动上传、不写入公开日志、不参与默认云同步。
- X-ASR 继续作为默认引擎；VoiceKey 是真正的第二套可选识别路径。未经同机测量不标注“更快”“更准”，不自动改默认，不静默回退云端。
- 原九键/全键、QQ 输入法风格参考下的独立原生设计、明暗主题、系统按键反馈、资料面板及备份不能退化。参考交互不复制其他产品商标、皮肤或受限素材。
- 云剪贴板与永久收藏分离。同步采用用户主动启用、自持恢复材料、增量/合并/退避；不每次输入或识别都读写 R2。
- 服务端继续独立 Go/PostgreSQL、自有服务器中转、Cloudflare R2 密文存储和一键部署路线；不把服务器身份验证误报为完整同步。未经许可不操作用户电脑、手机、生产服务器或 DNS。
- 英语伴学保留在后续计划：中文确认上屏后展示参考英译，主动收藏积累；不扫描应用全文、不把识别过程中的临时文字直接用于学习，不用示例文本冒充真实翻译。

## 3. 语音产品形态

当前交付只要求“单次会话选择一个本地引擎”，降低耗电、复杂度和故障传播。默认录音流程为：选中引擎及可信模型 → 显式录音 → 流式预览 → 停止并生成终稿 → 用户确认 → 原输入事务最多插入一次。

后续可增加本地模型预热、缓存释放、停顿结束、热词、数字/标点整理以及实验性双引擎对照。双引擎比较应优先使用同一段固定测试音频顺序重放，避免同时推理争抢 CPU 导致不公平。常规使用中的并行识别默认关闭。多渠道结果不得未经许可送给云端大模型仲裁。

云端增强和其他离线引擎是可插拔扩展，不是 Android Alpha 的先决条件。只有稳定、获得授权的 API 与明确的用户同意流程具备后，才接云端服务。VoiceKey 子模块包含某渠道源码，不等于 ZapIME 已支持或被授权使用该服务。

## 4. 分阶段执行与交付门禁

### V0 · 交接基线（已有基础，须重新核验）

代码基线 `e24f1bd21ecd4fca99d909a972116e5a36e5f6c2` 已有 VoiceKey 源码固定、离线适配器、Android JNI、模型导入和切换界面。六条 CI 在本轮核验时均为 success，包括双 ABI 构建及 API28/35/36 既有回归。它们不替代 VoiceKey 模型驱动的专项验收。完整证据和限制见 [验收矩阵](VOICEKEY_ACCEPTANCE.md)。

### V1 · 双引擎正确性与安全收口（最高优先级）

交付：引擎选择真正贯穿启动入口、模型验证、录音、预览、终稿和退出的完整实现，以及针对性自动化回归。

首先修复 `ZapInputMethodService.startVoice()` 仍仅检查 `VoiceModels` 的问题，增加仅装 X-ASR、仅装 VoiceKey、两者都装、均未安装、已选模型损坏五类用例。然后审计静音/空 PCM、迟到回调、输入框/选区变化、取消/超时后的真实推理停止、有界队列、模型缓存替换和 JNI 异常边界。

所有资源和授权检查必须与真实实现相符。仅有“已下载目录”不能表示模型可用；安装后自生成 SHA256 清单不是原始模型可信来源证明。详见 [整合方案](VOICEKEY_INTEGRATION.md)。

### V2 · 云端可完成的测试与试用包

交付：固定提交、锁定依赖、双 ABI 开发 APK、必要的模型获取/导入说明、文件校验值、离线使用步骤、已知问题和真实测试报告。使用受保护的临时模拟器执行测试，不使用个人设备上的破坏性 CI 脚本。

保留原 X-ASR 门禁，并新增明确切换到 VoiceKey 的模型加载/实际 JNI 解码/预览/确认插入/取消测试。若尚无可合法用于 CI 的 VoiceKey 模型，报告明确标为 BLOCKED；仍完成无模型单测、安装器攻击面测试、全部可执行的构建与回归，不能虚构识别成功。

区分“可供用户真机验收的候选包”与“已通过真机的 Alpha”。没有用户设备时继续完成所有非真机事项，最后集中给出一次真机操作单，不因缺少手机而停在代码计划阶段。

### V3 · 三星 S25 真机 Alpha 与效率比较

交付：同一台 S25、同一模型版本和同一测试语料的两引擎对照报告，以及能交给用户和朋友使用的 Alpha。

必测：安装/升级/备份、只安装各自模型、飞行模式、冷/热启动、首字与定稿延迟、短句/60秒边界、中英混输、数字/金额/日期/术语、停顿/底噪/权限撤销/蓝牙、键盘隐藏/切编辑器/移动光标、取消后再录。真实人声数据须单独同意，默认留在本机；公开 CI 只归档合成或明确可公开的材料。

性能报告必须记录设备、系统、CPU/线程配置、模型 SHA、语言、录音时长、是否按实时速度喂音、冷/热状态、P50/P95、样本数及失败数。使用 CER=(替换+删除+插入)/参考字符数；不得用 100%-CER 冒充“识别准确率”，不得把重复同一句当新增样本。

不预设哪套引擎胜出。速度、文本质量、内存、能耗和稳定性一起决定推荐档位；稳定 NEON 编译修复可能改变性能，必须在 ARM 实测后再优化。

### V4 · 体验优化和可选多引擎

V1/V2 闭环后继续做可验证的预热与闲置释放、结果稳定显示、端点检测、热词、专有词及数字后处理、可取消的长句定稿。对比模式和流式直接上屏须单独设计；默认仍保留“预览后确认”。真正上屏前继续使用既有焦点/选区/隐私事务，不能直接照搬第三方粘贴实现。

### V5 · 四端语音与完整产品延续

Android 交付后在 Windows TSF、macOS InputMethodKit 复用经过验证的识别接口与工作进程，分别验收原生激活/真实输入/安装签名。iOS 采用主 App 录音/识别与键盘接力，遵守系统权限和生命周期，不声称键盘可直接收音，也不承诺绕过后台限制。

并行推进既有路线：E2EE 配对/资料库绑定/持久上传与认证拉取、四端短语与词库同步、灾备恢复、一键服务部署、英语伴学。它们有各自验收，不得因语音 CI 通过而标记完成，也不作为首个 Android 双引擎试用包的阻塞项。

## 5. 验收与发布规则

| 层级 | 可声称的结果 | 必须具备的证据 |
| --- | --- | --- |
| 源码 | 接口、UI 或适配代码已提交 | commit、具体文件、审查差异 |
| 构建 | 某平台包成功编译 | 相同源码的 CI、真实非空产物、ABI/JNI/依赖/署名检查 |
| 基线回归 | 既有功能未发现所测回归 | API/机型/用例/原始结果；明确当时选中的引擎 |
| 专项识别 | VoiceKey 模型驱动闭环通过 | 引擎 ID、模型 SHA、实际解码和编辑器正文证据 |
| 真机 Alpha | 用户可在指定设备试用双引擎 | S25 实测记录、已知限制、升级/备份/卸载说明 |
| 稳定发布 | 达到支持范围内的产品门禁 | 上述证据、正式签名策略、许可材料、资源/质量指标和回归 |

PR 可以拆成可独立审查的安全代码切片；在没有完成的能力关闭且不影响主线时，按仓库审查规则决定合并。合并不等于对用户宣称真机完成。不得靠降低断言、删除失败记录、忽略格式/测试错误或变更测试样本获得假绿。
