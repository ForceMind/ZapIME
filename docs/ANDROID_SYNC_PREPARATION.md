# Android 本机同步密钥准备

更新：2026-11-06。实现位于 `feat/android-sync-preparation`，基于 Android 双离线候选分支。当前已通过主机回归与 Java 编译；新 JNI、Keystore 及页面生命周期等待对应提交的 API28/35/36 CI，不能沿用旧语音包的通过结论。固定 `08e84980` APK 不包含本页新功能。

## 这一切片提供什么

在“服务器与设备连接”中，用户主动打开“本机加密同步准备”，可以创建首次使用的本机密钥、继续中断的准备、导出密钥恢复文件与独立43字符恢复码，或导入原有密钥。所有操作由独立 SyncWorker 执行，准备页面不调用 HTTP、不上传资料、不启用后台轮询。

**准备完成只表示本机受保护材料与资料库身份相符。** 它不是服务器密钥登记、双设备配对或资料已同步。服务器设备令牌也不是数据解密密钥。后续设备应导入同一份密钥恢复文件；本机缺少材料、远端暂时没有记录，都不能证明账号从未有过密钥。首次创建必须显式选择，页面说明无法判断其他设备的密钥状态；实际上传接入前还需解决远端密钥身份登记与冲突。

## 使用步骤

1. 在“服务器与设备连接”验证并保存设备连接；首次身份验证会联网。先打开本机个人资料页完成已有资料库初始化，再进入准备页。缺库不会由准备操作自动创建或迁移。
2. 首次建立一套资料时，管理员设备可明确选择创建。已有密钥的设备或成员设备应导入相同恢复文件；保存在本机但尚未绑定的材料可继续完成，重试不生成另一把密钥。
3. 准备完成后选择导出位置。通过系统文件选择器创建恢复文件，写入并读回一致后才显示恢复码。请手抄到可信位置，与文件分开保存；可在本页输入43个字符核对。当前不提供自动复制，离开页面会清除显示和输入，不承诺 Java 字符串的物理擦除。
4. 导入时先选择原恢复文件，输入它的恢复码，再明确确认。认证后核对账号、key ID 和资料库中的材料指纹；只接受原材料或未绑定的新库，不替换另一套密钥，不覆盖个人资料。

文件只含同步根密钥及认证的账号/key ID，**不含词库、收藏、剪贴板、账号令牌、同步历史或语音模型**。仍须另行保存个人资料/服务器备份。仅保存服务器密文、设备令牌或这个恢复码中的任一项，都不代表具备完整灾备能力。

## 实现与失败边界

- Rust `workspace::Material` 为固定72字节格式，含版本、账号 UUID、key UUID 和32字节根密钥；没有 Debug/Display/普通 Serialize。秘密通过 byte[]/Zeroizing 缓冲进入独立 Keystore 材料域，不经过业务 JSON 或 SharedPreferences。
- 恢复文件使用已有 XChaCha20-Poly1305 / 固定 Argon2id 封装，增加同步材料专用用途、账号和 key ID。拒绝本机资料备份被当作同步密钥包；固定上限16KiB，不接受调用方自定 KDF 参数。
- Vault 创建只允许首次写入；相同字节幂等，不同材料或不可读密文拒绝。先持久化并解密读回，再以已有 SQLite v2 的 IMMEDIATE 事务绑定账号、key ID 和完整材料的 SHA256 指纹。
- 两种存储不是跨文件原子事务。材料保存成功而数据库失败时保留材料，供同材料继续；库已绑定但材料文件缺失时不能新生成，须恢复原包。同 key ID 但不同根密钥也不能绕过指纹检查。
- 数据库绑定不修改 records、operations、冻结请求、收据或拉取 cursor。拒绝旧孤立同步历史、损坏/未知身份、未来 schema；新建绑定与本机资料恢复都拒绝异常 `sync_` 元数据。
- SQLite busy 等待和合作 VM 预算各200ms，预算不是硬实时保证；大库和手机输入延迟仍需专门测量。所有操作不占用输入/语音 worker。
- 页面防截屏，禁止恢复码状态保存、自动填充和学习；暂停/停止清秘密并使旧 generation 失效。已经开始的原子保存或数据库事务可能完成，不能承诺离开即回滚；返回页面重读实际状态。

**尚未支持的原地修复：** 若旧密文仍存在但 Keystore 包装密钥丢失，或旧密文已损坏，本页不会删旧文件、换包装密钥或覆盖。正确恢复包可在全新本机环境导入；原地修复还需要单独的、证明同根材料后的显式流程。逻辑删除、辅助材料加密都不等于整个本地 SQLite 已静态加密。
