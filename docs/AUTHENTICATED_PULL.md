# 密文页验证与事务应用

`zapime-sync::apply_encrypted_page` 是共享的下载验证入口，尚未接入 HTTP、四端宿主、账号界面或系统密钥库。测试用两个独立 SQLite 库、真实 XChaCha20-Poly1305 密文和模拟的 v1 操作流，不是联网、Cloudflare 或四端真机互通验收。

## 验证与提交

1. 输入最多 10 MiB，严格拒绝未知/重复字段及追加 JSON；changes 在反序列化时限制为 100 条。
2. 检查账号、UUID、有界连续修订、next_cursor 和 head。v1 服务在账号锁内逐次加一且不压缩历史；缺口/乱序、空页跳向 head、低于已应用 cursor 的 head 都不能前进游标。
3. 使用调用方已加载的本机密钥版本，不在此函数调用网络。缺少旧版本密钥则整页停止，不跳过无法解密的条目。
4. 按账号、实体、操作、密钥版本和 kind 认证解密，核对完整 Record 的 ID、类型和删除状态。不能只相信外层 deleted。
5. 整页全部认证后才进入 SQLite IMMEDIATE 事务，再检查账号绑定和 expected cursor。记录、上传回声确认、持久收据和 cursor 同事务提交，任意错误全部回滚。

`Store::apply_verified_pull` 是受信任代码的存储边界，不自行执行 AEAD；宿主只应使用前述验证入口，不能把服务器 JSON 直接转为 RemoteRecord。公开 Rust API 与同进程数据库访问不是相互隔离的安全域。

## 修订、回声和重放

下载不生成本地待发操作，避免设备间回声循环。发送方 Record.revision 不当作本机或服务器修订：本机新增从 1 开始，更新递增自身修订，服务器映射另存。恢复导入且尚未映射的本机记录，只有正文/删除状态一致才认领远端版本；不同内容停止。

自己的回声必须匹配已冻结的完整 UploadOperation 和不可变 Record 快照。确认不覆盖后续离线编辑；提前确认的较新上传不会被旧拉取历史倒退。确认上传本身继续不推进 pull cursor。

兼容 SQLite v2 的 sync_received 辅助表保存操作 ID、服务器修订和规范化摘要；sync_pending_record 索引支持待发检查。已收到操作不能靠改变外层 revision/base_revision 再应用，避免旧的已认证创建操作复活墓碑。新的、基于当前墓碑修订的显式恢复仍允许。旧 v2 写入兼容，不改变开放归档 v1。

迟到/重复页因 expected cursor 不匹配而拒绝，没有第二次副作用；调用方须重读本机 cursor，不无限重试旧页。没有裸游标跳转；空页不把 head 当作已下载位置。

## 冲突与认证边界

遇到本机待发、不同内容的未映射恢复记录、类型变化、候选位置或词库语义冲突时整页回滚，本机正文、冻结请求、事务内较早确认、收据和 cursor 均不部分提交。本模块不自动覆盖或丢弃队首。

尚未实现永久冲突副本、失败密文页隔离落盘、图形比较/解决或绕过冲突同步其它条目。远端仍在服务器，调用方仍持有输入密文；回滚不是“冲突已解决”或“副本已离线保存”。服务器不可用时，尚未落库的远端冲突内容不保证已在本机备份中。

外层 device_id 是服务器报告的发布设备，既有 AEAD Binding 不包含它，不能称为客户端独立验证的作者签名。Record.device_id 是加密正文里的本地来源 UUID，可在建账号前生成，不必等于服务器设备 UUID。设备授权、正文认证和来源展示分别处理。

现有 AEAD 也不证明服务器 head 的新鲜性；服务器仍可能隐瞒操作。连续性、持久收据和墓碑检查不是可验证透明日志。配对、密钥轮换和平台受保护存储仍未接入。

开放归档 v1 不含同步收据/映射/cursor/凭据，恢复后必须显式重建状态，不能把旧 cursor 拷入只有部分数据的新库。crypto v1 的 64 KiB 明文上限包含 JSON 元数据/转义，最大的合法本地文本不一定能封装为单个对象；上传准备须明确拒绝超限并保留内容/队列，不能截断。本切片不改变密码或线上协议。

## 测试范围

13 项新增测试覆盖两库真实 AEAD 交换且无回声上传、修订分离、后半页篡改/缺密钥零部分应用、绑定/删除伪造、冻结回声和后续编辑、提前确认不倒退、冲突回滚更早确认、候选语义、恢复保护、分页/字段/大小边界、重启后反重放、显式墓碑恢复、双连接迟到页拒绝及认证过的替换密文也不能冒充冻结快照。具体构建与 CI 证据见 STATUS.md。
