# ADR-020 · 2026-11-06 · 双离线引擎优先交付与证据分层

状态：本轮产品/工程接续决策。补充 [DECISIONS.md](DECISIONS.md) 中 ADR-019；仅替代与下述明确变更冲突的实施描述，保留其他既有约定。

## 决策

1. **近期产品目标改为 Android 双离线引擎 Alpha。** 四端输入、统一数据、E2EE/R2 和英语伴学继续保留，不作为本次试用包的前置依赖。按 [新开发计划](DEVELOPMENT_PLAN.md) 的 V0–V5 接续，不重新启动旧 M0。
2. **VoiceKey 已引入，不再按“仅建议、未集成”描述。** 用户已确认作者同意源码整合；继续实现并保留授权记录，不反复请用户重复确认。第三方模型/服务/二进制权限仍独立，不能以此授权自动放行。
3. **完整源码保留与产品编译范围分离。** 固定 VoiceKey 子模块；产品只使用离线模块。当前四个模块从固定上游引用，INT8 kernels 为保留来源的本地稳定 NEON 补丁，不再说五个模块全部原样编译。不会因导入完整仓库而自动启用云识别。
4. **撤销已过时的 ARM dotprod 限制描述。** 旧 vdotq_s32 编译失败已改为稳定 NEON 运算；当前不依赖旧 CPU 门禁。此决定只描述实现与构建，不宣称全部 ARM 设备已验收或性能不变。
5. **CI 成功分层表述。** 代码 e24f1bd 的六条 CI 已成功，Android 双 ABI 和 API28/35/36 既有回归通过；VoiceKey 专项模型识别、S25、自然语音、签名与正式发布仍独立验收。后来的文档提交不能借用旧 CI 冒称同提交已跑。
6. **默认 X-ASR、统一录音、确认上屏。** VoiceKey 是第二套可选方案；预览/终稿和上屏权限分开。不会自动并行两个大模型、改默认或回退云端。
7. **修复必须由实际覆盖证明。** 优先修正所选引擎与 startVoice 准备条件不一致的问题，再验证取消/缓存/模型信任锚/PCM/JNI。构建能成功不是忽略这些缺口的理由。
