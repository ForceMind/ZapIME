# Android 手动加密同步（开发试用）

本切片接续本机密钥准备和服务器密钥身份登记。它提供用户明确确认的一轮有上限传输，不开启后台同步，不表示四端互通或完整设备配对已经验收。源码、实际测试与未运行项以 [STATUS](STATUS.md) 和本轮原始证据为准；旧双语音候选 APK 不包含这些功能。

## 准备与使用

1. 部署支持 `/v1/session` 和 `/v1/key-descriptor` 的 ZapIME 服务，使用有效 HTTPS 证书。服务器 PostgreSQL schema 为3；旧二进制不能直接打开新版数据库，升级前保存完整数据库与对象备份。
2. 在主应用“服务器与设备连接”中验证并保存设备凭据。首次在个人资料页初始化本机资料库。
3. 在“准备本机加密同步”创建首次密钥或导入原密钥恢复文件与独立恢复码。已有设备须使用同一套材料；设备令牌不能代替解密密钥。准备页保持零HTTP。
4. 打开独立的“核对服务器密钥”页面，核对账号、服务器、密钥编号和材料摘要。首次由管理员为没有同步历史的空账号明确登记；已有相同身份只核对。不同根或旧历史一律停止，不自动换根、删资料或重写冻结请求。
5. 打开“手动同步个人资料”，核对所显示的服务器、账号、设备及密钥摘要，再选择并确认本轮传输。每次确认仅针对当时显示的公开身份选择；在工作线程开始前或传输中发生连接、设备或根材料变化都会拒绝继续。

本轮包含本机待同步的词库、候选规则、短语、永久收藏和明确保存的剪贴板，以及修改/删除操作。正文在本机加密；服务器仍能观察类型、操作与设备等元数据。语音模型、录音、编辑器上下文、根密钥、密钥恢复文件和恢复码不在资料传输范围。

## 传输与资源边界

每轮先以一次GET核对服务器登记的密钥身份，再从本机持久游标拉取至多2页（每页100条）。只有追上本轮所见head后才上传，最多16条。若有上传，再读取至多2页以确认回声与远端更新；没有上传时不重复一次无用拉取。无后台轮询、自动重试或逐次输入请求。

- 每次POST之前先在SQLite中冻结完整操作快照及随机nonce密文请求。网络重试使用数据库原字节，不能重新序列化或按最新记录生成另一份请求。
- 成功HTTP不是本机确认：ACK还须通过账号、服务器设备、修订、完整操作及真实持久stage的一致性验证，实际AEAD解密须等于不可变原快照。未stage的ACK不能创建stage；ACK不推进拉取游标，也不覆盖后续本机编辑。
- 拉取只调用共享的整页认证、原子应用和失败页保留边界。坏后半页不留下前半页，冲突不静默覆盖本机内容。符合保存条件的原失败密文页独立保留；`saved`、`not_eligible`、`failed`有不同结果，不把回滚视为保存成功。
- 单条请求/ACK各100000字节，整页10MiB，完整Record明文编码最多65536字节。超过编码上限的原文本和pending保留，不截断为可上传文本。正文接近64KiB时加上UUID/修订等也可能超限；若它是最早pending，会暂停后续上传，当前不跳过它或改写历史，UI明确报告大小上限。
- 每次HTTP有12秒合作预算；一轮90秒合作预算和固定操作/页数上限。DNS、输出流、磁盘与系统调用不具强制硬中断保证。取消或离开页面后，已到达服务器的请求、已经开始的本机事务可能完成；迟到UI结果被丢弃，未确认操作仍保留原冻结请求。
- 所有网络、Keystore和资料操作在独立有界同步worker，HTTP期间没有SQLite事务或vault锁。输入/语音worker不等待网络。SQLite写入使用existing-v2连接，无创建、迁移、清库；busy和SQLite VM各200ms合作预算，不包括解密或磁盘硬截止。

服务器 `/v1/key-descriptor` 只操作PostgreSQL，不读写R2。资料POST在授权、幂等、冲突与配额校验后才写对象。客户端离线编辑合并只处理有界未stage窗口，不改变已冻结请求；HTTP逐条发送仍是逐个对象，不把操作合并称为R2对象合批。管理员仍应按 [部署文档](SERVER_DEPLOY.md) 设置对象后端与备份，不能由“默认本地”推导零云账单。

## 当前不支持与恢复边界

同步落库后，词库与候选规则在下一次新输入会话重新加载；已保留组字的当前会话不会即时刷新。请离开并重新进入输入框后试用新词，资料面板重新查询则读取最新数据库。当前不通过按键路径扫描全库或强制清空组字来刷新；实时内存快照安装仍待独立实现和验收。

- 冲突目前会停止整页，并保留本机资料及合规失败密文页；永久冲突副本、逐项解决和重建修订流程仍需独立实现。
- 只有当前已恢复的这一把根密钥。历史其他key ID不会猜测或自动获取；服务描述符不是持有证明、真正配对核对码或抵御恶意服务器回滚的机制。
- 两台设备各自产生不同根时，只有一套能首次登记。失败一方保留资料和恢复材料，当前没有原地自动换根或将旧密文重加密成新请求的流程。
- 令牌到期/撤销、R2错误、服务器恢复后的历史倒退、未知schema都会停止。没有后台重试，须由用户处理后再手动继续。
- 正文SQLite不因同步材料被Keystore保护而自动整库加密。逻辑删除不等于物理擦除，永久收藏也不依赖剪贴板自动过期。
- 密钥恢复文件不含个人资料；个人资料备份不含根密钥、设备凭据或完整同步历史。继续分别保存资料备份、密钥包和独立恢复码，以及服务器数据库/对象备份。新设备与全新服务器完整灾备、历史迁移和四端互通需单独验收。

## 验证口径

共享Rust测试验证真实AEAD、两库交换、不可变请求与ACK/整页边界；主机Java回环TLS验证真实传输和限制，策略测试只验证顺序、预算和取消。Android离线探针验证真实JNI/Keystore/Editable或页面，合成服务器外层不是实际HTTPS交换。实际Go/PostgreSQL服务与共享客户端交换另设独立CI；上述任一层都不替代Android手机HTTPS、跨设备或生产部署。未运行项目必须保持NOT RUN。
