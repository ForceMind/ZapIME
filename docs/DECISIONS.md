# 技术决策

## ADR-001 · 2026-10-20 · 固定上游，渐进迁移

MSIME 使用精确提交的 Git submodule 保留完整可追溯源树与四端原生宿主；ZapIME 扩展位于根工作区，不批量改写上游源码。首个 Android 验证宿主为独立原生 InputMethodService，复用原拼音引擎 Session，不携带上游联网服务。候选代次由薄适配层核验。

这让离线核心和独立标识可以先实际构建，代价是首包不包含上游成熟键盘的所有功能。M1 仍须逐步移植上游输入运行时、键盘交互与其余宿主；四端不会因 submodule 存在而被标为完成。

## ADR-002 · Android 身份与默认网络边界

使用 org.zapime.android，与上游 app.msime.android 隔离。首个开发包无 INTERNET 权限，不运行账号、更新或资源下载服务。构建时获取校验过的拼音与英文词库，运行时离线。临时不提供模型权重、语音、辅助码、剪贴板。

## ADR-003 · 后端独立实现

msime-cloud 未发现覆盖第一方实现的明确授权。只记录协议观察，不复制实现。后续自建服务独立开发，使用客户端密文、设备认证与基于修订的冲突处理。

## ADR-004 · 统一数据与恢复封装

共享 SQLite 采用事务修订与操作幂等，开放归档采用显式明文格式。恢复包在外层使用 RustCrypto XChaCha20-Poly1305 和固定资源参数的 Argon2id，同时封装根密钥与归档。恢复码独立保存，服务器不掌握解密后门。模块级恢复演练先于云端接入；不把它标作四端或空服务器恢复验收。

## ADR-005 · 2026-10-22 · 公开授权与 Apple 最小原生宿主

用户明确要求保持 Public，覆盖早期 Private 约定。继续禁止提交凭据和真实输入记录，不修改既有许可义务。

macOS 与 iOS 通过版本 1 的有界 C ABI 调用现有 ZapIME InputSession，保留 MSIME 固定引擎。宿主身份、缓存和资料路径均独立；未批量修改 vendor。macOS 使用 InputMethodKit，iOS 使用 UIInputViewController 原生扩展。先保留不学习的离线模式，不引入上游账号/网络服务，也不把共享库检查当作宿主验收。iOS 通过专用 Thread 保持 Rust 会话线程归属，主线程只渲染状态及操作文本代理；焦点代次过滤迟到结果。

本切片以原生编译和桥接测试为门禁；系统激活、真实应用输入、键盘扩展内存、签名与分发仍需单独验证。

## ADR-006 · 2026-10-22 · Windows 原生隔离边界

上游完整 Windows TSF 与独立 Server、配置、云端协议及品牌版表绑定。首个 ZapIME Windows 切片采用最小原生 TSF/COM 宿主直接调用同一个有界 C ABI，解码器不重写；研究上游工厂生命周期、编辑锁和注册回滚，保留固定子模块供后续成熟交互迁移。仅声明实际实现的 keyboard category，关闭学习和联网，不提前声明安全桌面/UILess 等能力。

CI 在 Windows SDK 下编译真实 DLL，并装载工厂和核心进行边界测试。未经系统安装和真实客户端输入验收，不将其记作完整 Windows 输入法完成，也不将新的最小宿主等同于上游全部成熟功能。nlohmann/json 固定 v3.12.0 和归档 SHA-256，保留 MIT 文本。

## ADR-007 · 2026-10-22 · 独立密文服务与事务同步基线

服务端从空白实现，不复制未获明确许可的 msime-cloud。优先用 Go/PostgreSQL 的账号行锁建立可验证的线性修订、幂等与撤销；不以本机时钟覆盖冲突。服务仅处理 zapime-crypto v1 envelope，服务访问凭据与 E2EE 解密材料分离。初期账号/凭据通过管理员 CLI 管理，不伪装成已完成图形账号和双设备核对码配对。

先验证真实数据库、Docker、两设备密文交换和空数据库恢复，随后才接四端异步客户端。备份脚本不覆盖已有文件；恢复拒绝非空库。账号保守配额满时拒绝写入，不自动删除收藏或墓碑。生产前仍需速率限制、监控、安全审计、密钥托管与设备配对。

## ADR-008 · 2026-10-22 · 不可变上传请求与独立修订

SQLite v2 为离线操作引入显式持久自增序列，避免以 VACUUM 后可能改变的隐式 rowid 作为上传顺序。待发正文取自创建操作时的快照，不能在重试时替换成记录的后续编辑。首次 AEAD 密文请求持久化后原样重试，避免同一 operation_id 因重新随机生成 nonce 被服务端拒绝。

本地记录修订、服务端实体修订和账号拉取游标分开保存。上传确认只原子更新待发状态、确认凭据与服务端实体修订，不覆盖业务记录，也不推进拉取游标；否则可能跳过其他设备的并发写入。账号绑定阻止跨账号误上传。远端认证应用、冲突解决和游标原子推进另行实现，不以这些准备接口冒充已联网的同步客户端。

SQLite 内部版本升级与开放归档版本独立；旧程序拒绝打开 v2，降级需先导出开放归档并恢复到旧版全新库。新增密文暂存不改变本地 records/operations 仍含明文的事实，完整静态加密与安全清除仍待实现。

## ADR-009 · 2026-10-22 · 原生键盘设计与退出验收

按用户要求参考 QQ 输入法的紧凑布局，Android 采用四排键位、共用工具/候选区域与独立数字/符号面板；图标由 ZapIME 自行用 Canvas 绘制，不引入第三方皮肤、QQ 标识或联网入口。设置与个人资料使用同一组原生视觉组件。新 UI 不改变 Rust 输入核心、焦点代次与候选代次校验。

原生截图和输入断言不能替代运行时日志复核。UI 改造的首次两轮输入 PASS 后，日志暴露既有 onDestroy 生命周期顺序错误：父类 onDestroy 同步进入 onFinishInput 时，worker 已经 shutdown。必须先完成父类回调，再在核心所属线程关闭 handle 和 worker；关闭动作清零 handle，避免重复释放。CI 在受保护的临时模拟器里按轮清空旧日志、切回 AOSP 输入法、确认服务退出并拒绝本轮 ZapIME fatal。不能把清空日志扩展到用户日常设备。
