## 1. 背景与要解决的痛点

用户当前在 Android、iOS、macOS、Windows 各自使用不同输入法，自己的拼音词库、候选词优先级、快捷短语和剪贴板无法互通，非常影响体验；更担心某输入法运营商关闭服务器后，自己多年保存的内容全部消失。

**ZapIME 的本质，是一款真正的四端原生输入法 + 用户自己掌控的同步与数据保存系统。** 不要求改造三星/搜狗/Gboard 等已有输入法，而是构建 ZapIME 独立输入法。

产品原则：
1. 本地优先、离线可用。网络断线不应影响正常输入。
2. 用户永久拥有数据，能完整导出、加密备份、在另一台设备或一台新服务器恢复。
3. 一套账号和数据模型贯穿 Android、iOS、macOS、Windows；四端原生宿主可以不同，但核心数据必须同步。
4. 同步服务自建、可部署在用户控制的服务器上，**官方水杉服务不可成为核心依赖**。
5. 云剪贴板采用端到端加密，保留用户可用的恢复包/恢复码，不因全部设备遗失而使已妥善备份的数据无法恢复。
6. 临时云剪贴板与永久收藏必须分离；收藏不会因剪贴板保留期或 50 条容量而被清理。
7. 候选规则必须有显式用户控制，不能无条件交给 AI 覆盖可信词典命中。
8. 技术文档成熟、中性、具体，不写“某个人维护”等无意义宣传；严格保留法律要求的上游归属、许可证和第三方 NOTICE。

## 3. P0 产品交付内容：四端输入 + 数据闭环

**基础真实输入法**：Android InputMethodService、iOS UIInputViewController 键盘扩展、macOS InputMethodKit、Windows TSF；四端必须完成本地中文全拼、英文、标点、候选选择、删除、输入框焦点切换和离线输入。

**自定义候选字词**：个人词库、按输入方案的编码词条、词组、排序、置顶与固定候选位置、用户明确的覆盖规则。例如 wx 对应特定短语、zhong 优先显示指定汉字；编辑后本机立即生效并能跨端同步。词典精确可信命中不被不可靠 AI 强制扰乱。

**快捷短语**：例如 wx → 联系方式、gs → 公司信息。管理新增/编辑/删除/标签、分类、导入导出、跨端同步；以后再加动态变量/宏。

**剪贴板**：本地剪贴板历史、搜索、固定、删除；用户明确选中某条后发送到云端；其他设备从云端列表点击插入，不需系统剪贴板二次复制；有敏感信息过滤、过期保留、加密传输、设备授权；永久内容可转存“收藏/常用语”。自动上传云端默认关闭。

**统一自建同步**：独立身份和设备系统、增量同步、断网队列、冲突合并与 tombstone 防复活、幂等操作、版本与协议兼容；同步用户词库、候选规则、快捷短语、收藏、跨平台可共享设置（平台独有设置留本地）。

**数据与恢复**：客户端标准数据导出和导入、密码保护的完整加密恢复包、恢复码/密语、新设备配对、撤销、密钥轮换、灾备；要求真实演练“官方云消失/自建服务器空库/手机重装/四端恢复”。备份须包含明确选择的输入习惯、重要自定义数据和永久收藏，不依赖只保存 50 条的云剪贴板。

**隐私安全**：离线优先，默认不把按键/正文/候选流上传给第三方；密码、验证码、隐私框不进入学习、剪贴板云同步和诊断日志；端到端加密服务端看不到正文；移动端系统密钥库和桌面受保护存储；HTTPS、限流、审计、依赖扫描、可信资源校验。独立数据导出不应泄漏账号令牌。

**自主品牌**：ZapIME 标识、包名、帮助、关于、原生设置、安装及卸载与保留数据；不能意外共享水杉输入法的系统注册标识和用户数据路径。

## 4. 平台具体边界

- Android：优先建立 Samsung/Android 真机可安装的 ZapIME APK 和离线输入；只有 ZapIME 作为当前输入法并获得允许时才能按系统机制记录普通复制事件。用户未开启时不记录，默认不自动上传云。
- iOS：系统限制第三方键盘权限、后台执行与剪贴板访问；安全字段会切回系统键盘。使用原生键盘扩展及设置 App、App Group/Keychain；需要“允许完全访问”才可执行的联网功能必须明确说明；用显式粘贴/保存和前台刷新，不承诺全局静默监听。尽早验证 Xcode 构建与真机签名，不要把风险留到最后。
- macOS：使用 InputMethodKit 原生宿主，不用网页替代系统输入法；处理系统输入源安装、签名、公证和焦点生命周期。
- Windows：使用 TSF 原生宿主、独立配置目录与安全存储，测试微信、浏览器、Office/记事本及其它常见应用焦点与候选上屏。
- 四端输入界面保持一致的产品语义，但不强制共享全部 UI 代码；共用 Rust 业务与数据契约。键盘主线程永远不能等待网络。
- 用户其他已有输入法的个人词库只通过可获取的正规导出接口迁移，无法导出的不可宣称自动提取，不实施 root/越狱或绕过保护的默认方案。

## 5. 技术架构建议

- 尊重上游已形成的 platforms/android、platforms/ios、platforms/macos、platforms/windows、crates/engine、crates/input-runtime、crates/host-api 结构，避免大规模无意义重命名导致后续难以合并上游修复。
- 在合适位置增加 ZapIME data/crypto/sync 模块，采用统一版本化 schema、本地 SQLite 或平台适合的可靠存储、端到端加密和本地搜索。
- 后端优先独立 Go + PostgreSQL，提供账户、设备、同步 cursors、对象变更、云剪贴板密文、密钥封装与审计；支持 Docker Compose、TLS 反代、自行备份与新环境恢复。
- 同步以操作 id、稳定实体 id、单调修订、删除墓碑、确定性冲突合并为原则；不靠设备本地时间戳最后写入胜出。
- 提供用户自持恢复密语/密钥备份，不能声称仅凭服务器上的密文就能找回失去的密钥。
- 优先采用现有经许可可使用的加密协议和实现，禁止随意自创加密算法。
