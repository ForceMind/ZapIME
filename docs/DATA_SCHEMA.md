# 本地个人数据与开放归档

实现：`crates/zapime-data`。Android 已接入本地管理与输入；其余平台管理和四端联网同步未完成。SQLite 内部版本为 2，开放归档仍为 1，二者分别演进。

## 记录与修改

每个 Record 有 UUID、revision、device_id、deleted 和 Content。Content 为明确的带类型数据：Dictionary、CandidateRule、Snippet、Favorite、Clipboard。候选位置为 1–40；编码必须是规范化的小写字母、数字或分词符。相同正文但不同编码是不同记录，不错误去重。

Store.edit 接收稳定 operation_id、expected_revision；新记录 expected_revision=0。记录与待发送操作在同一 SQLite IMMEDIATE 事务写入。重发同一个操作且参数相同返回原结果；复用操作 ID 修改参数则拒绝；旧修订不能覆盖新修订或删除墓碑。不用本机时钟决定冲突胜负。

这些是本地修订，不能直接当作云端 revision 或拉取 cursor。SQLite v2 通过独立表保存不可变待发快照、暂存密文请求、服务端实体修订及确认凭据；上传确认不推进拉取游标。详见 [SYNC_STATE.md](SYNC_STATE.md)。配对身份、平台密钥托管、远端应用与冲突副本仍待实现。

## 开放归档与恢复

导出为 UTF-8 JSON：`body.schema_version=1`、按 UUID 排序的 records，以及 body 序列化后的 SHA-256。该 SHA 只能检测意外损坏，不是防攻击签名。已实现的加密恢复包为另外一层（zapime-crypto），不能将本开放格式宣传为已加密。

首版只允许恢复到空资料库。导入前验证大小（32 MiB）、记录数量（100000）、schema、校验和、UUID 唯一性、修订边界和各类型字段；验证通过后一次事务写入。已有资料库直接拒绝，避免隐式覆盖。归档不含账户令牌、设备认证凭据或密钥；离线操作队列不导出，向空服务器重建同步仍须 M3 的重新登记流程。

当前删除为逻辑删除，历史正文仍可能存在于本地记录与待发操作，导出也包含墓碑，不能视作安全擦除。发布前须实现正文清除策略与过期操作压缩，结合 OS 受保护存储和加密恢复格式。

## 收藏与剪贴板

Favorite 不含过期时间。Clipboard 必须显式指定 expires_at_ms；置顶只影响展示，不覆盖显式的过期时间。expire_clipboard 只对到期临时条目写入删除操作，不删除收藏；删除墓碑保留以防离线重传复活。当前没有后台自动捕获或云上传。

## 已有测试

事务持久化/重试、同操作不同请求拒绝、过期修订冲突、不同编码保留、剪贴板过期不删收藏、墓碑归档恢复、损坏与未来版本拒绝、非空资料库不覆盖。UI、四端同步与设备授权仍待实现。

## 输入会话接入（M2 进行中）

zapime-core 在非私密会话读取 `data/personal.sqlite3`，缓存有效词条。整段编码精确匹配时，个人词库/快捷短语进入候选；候选规则按显式位置覆盖，普通拼音仍由 MSIME 解码。空组字不显示个人短语。用户候选选择与空格上屏走同一映射，并保留 generation 校验。私密会话不加载该资料库，也拒绝个人数据编辑。

Android 验证键盘支持长按当前候选置顶，写入持久化规则，重开会话继续生效；Android 原生离线管理页已提供新建/编辑/删除、明文归档导出和空库恢复入口（Storage Access Framework）；尚未完成四端管理与加密恢复 UI。测试覆盖规则重开恢复、快捷短语实际提交、置顶与旧候选拒绝。相同编码的候选槽位/文本冲突及词库的方案+编码+正文重复会被拒绝；导入也执行相同语义校验。长按另一个候选会替换当前编码的首位规则。编码语义的进一步标准化、四端适配与完整发布验收仍待完善，不能据此宣称 M2 完成。
