# 本地优先与同步用量

## 已实现与待接入

客户端目前仍是离线开发包，实际网络调度、远端应用、配对与四端同步尚未接入。下面区分已验证服务行为与客户端接入目标；部署服务不会自动让客户端开始上传。

| 操作 | 本地/自有服务器 | R2 行为 |
| --- | --- | --- |
| 拼音解码、候选、上屏、英文、使用已有短语 | 本地输入引擎/SQLite | 无 |
| 搜索、浏览、插入已下载的收藏或剪贴板 | 本地数据 | 无 |
| 本机剪贴板采集、设备专有设置 | 留在本机；云剪贴板需显式发送 | 无 |
| 编辑可同步词库/规则/短语/收藏 | 先写本地；后台上传准备已有，网络待接入 | 服务每个首次成功 Change 一个 PutObject |
| 查询服务器更新但没有新记录 | PostgreSQL 按 cursor 查询 | 无 Get/List/Head/Put |
| 下载新的变更记录 | 服务先鉴权、再按数据库索引取密文 | 每个缓存未命中的对象一个 GetObject |
| 账号/设备列表、授权、撤销 | PostgreSQL | 无；已有设备本地副本无法远程收回 |
| 完整备份、完整对象校验 | 独立管理命令，绕过缓存 | 每个被引用对象一个 GetObject |
| 恢复到另一个空桶 | 管理命令导入并验证 | 每个对象 PutObject，再读取验证 |
| healthz | 检查数据库 | 无 |
| 显式 check-storage / 安装存储检查 | 真实合成探针 | 一次 Put + Get + Delete，失败时可能重试 |

R2 Standard 当前免费额度每月 100 万 Class A、1,000 万 Class B、10 GB-month。Put 与 List 属于 A，Get 与 Head 属于 B，Delete 免费。额度按账号相关用量计算，不是每个设备/桶各一份；不适用于 Infrequent Access，超额会计费。来源（2026-10-23 核查）：https://developers.cloudflare.com/r2/pricing/ 。

## 服务端请求减少（已实现）

- HTTP 服务默认使用 16 MiB 密文字节/键及估计条目开销预算的内存 LRU；每条存活最多 10 分钟，访问不延长寿命。容器重启即清空，不属于备份或持久性保证。
- 成功写入后预热缓存；其他设备随后下载同一条记录可直接复用。相同键的并发缓存未命中只共享一次后端读取；首个设备断开不取消其他等待者，共享读取有 5 秒超时。
- 键含账号 UUID 和内容 SHA256，只缓存验证过的不可变密文；失败不缓存。鉴权、撤销检查与增量 cursor 查询在使用缓存之前执行。返回独立副本，避免调用者改坏缓存。
- 写入始终等 R2 成功，不能用内存缓存冒充云端持久化；幂等 HTTP 重试通常从数据库和缓存取原结果，不重复 Put。真正对象重复条件写可能产生 Put + Get，SDK 失败重试也增加操作数。
- 备份、verify-objects、恢复验证绕过在线缓存，真实验证持久对象。缓存存在时，手工删改 R2 对象可能直到过期/淘汰才被在线读取发现；管理校验会立即检查后端。不要在桶控制台删除历史或设置自动清理。
- 正常同步按 PostgreSQL 索引取对象，不扫描/列举存储桶，不用 HEAD 轮询每条记录，也不向公共 CDN 暴露用户密文。

## 客户端调度目标（尚未实现）

1. **输入只用本地数据**：同步后台执行，不把按键流、每次选词或每次搜索当成云操作。统计学习若以后开启，在本机累计净变化；隐私/密码/禁止学习字段排除。
2. **持久离线队列**：先落本地；相同记录在尚未冻结发送快照前合并重复编辑，2 秒防抖、最多 30 秒等待。删除保留墓碑，存在冲突时保留双方。已准备/已尝试发送的操作 ID、正文和密文不得因合并重写；确认只清理对应快照，保留后续本地编辑。
3. **按场景刷新**：启动/回到前台查询增量；前台活跃 60 秒一次、无变化逐步延至 5 分钟。手动“发到云端”立即上传；打开跨设备剪贴板面板在距上次检查超过 5 秒时刷新，并提供手动刷新。多个触发共用一次正在进行的同步。输入面板不等待刷新。
4. **省电与平台边界**：后台优先暂停常规轮询，按各平台允许的系统作业补同步；iOS 不承诺后台常驻或固定周期。网络恢复后重试，失败指数退避并加入抖动，最长 5 分钟；401/403 提示重新授权而非无限重试，429 尊重 Retry-After。
5. **一致性优先**：仅下载 cursor 后增量，验证并原子应用成功后才推进 cursor；断网/错误不丢队列、不跳记录。显示“待同步/上次成功/失败”，手动同步可立即触发。自动同步是最终一致，跨设备立即可见需要在线并成功刷新。

这些秒数是初始产品目标，接入时需要耗电、前台/后台和多端测试后确认。服务器未来可加仅含修订号的通知，收到提示再拉增量；通知不会成为正确性的唯一依据。

**合并 HTTP 请求不等于合并 R2 操作**：当前 v1 一个已接受 Change 对应一个对象，即便以后一个 HTTP 请求装 100 条，也仍可能产生 100 次 Put。降低写次数的关键是在不可变发送快照之前合并本地净变化；真正多记录对象打包需要另行版本化协议与灾备测试，尚未实现。

## 估算与备份成本

以一个账号全部设备合计每天新增 1,000 个不可变同步操作、共 4 台设备、30 天为例：约 30,000 次正常 Put；每条由另外 3 台设备各下载一次，未缓存时约 90,000 次 Get。分别是当前免费 A/B 额度的 3% / 0.9%。缓存可进一步减少读取，但不能承诺固定命中率；SDK/失败重试、冲突、管理员检查和其他账号用量需另算。

**每日完整备份不是零成本**：当前安装器每天导出所有历史引用，每次 N 个对象约 N 次 Get。若本月从空库以每天 1,000 条增长，每天完整备份额外约 465,000 次 Get；若已有 10 万历史对象，则单是每日完整备份约 300 万次 Get/月。当前没有对象增量备份或安全历史压缩，不应以降低费用为由停掉必要备份或自动删历史。后续可做本机持久密文镜像、增量归档加周期真实全量校验；必须先完成全新数据库/新桶恢复演练。

记录永久保留的历史会同时增加存储与备份读数，当前每账号保守配额是 256 MiB。免费用量需在 Cloudflare 控制台核对；现阶段没有服务端账单硬停开关。不要为了“严格免费”阻塞本地输入：即使未来云预算暂停，仍须留存待同步队列并明确提示。
