# 客户端持久同步准备状态

实现于 `zapime-data::sync`，为后台客户端准备上传队列；尚未调用网络、应用远端记录、解决冲突或接入四端界面。不能把它称作已经完成的同步客户端。

## SQLite v2 与开放格式

在原有 records/operations/metadata 基础上新增 `sync_queue`、`sync_uploads` 和 `sync_versions`，并将 SQLite `user_version` 从 1 迁移到 2；迁移不重建、不删除既有记录或待发操作。未知的未来版本拒绝打开。开放归档仍为 schema_version=1，不包含账号凭据、密钥、游标和内部队列。

这是开发阶段的数据库升级。旧版程序会拒绝直接打开 v2 数据库；降级需要先由新版导出开放归档，在旧版全新资料库恢复，不能直接改 user_version 假装回滚。正式升级/回滚安装工程仍待 M6 验证。

## 账号与不可变操作

一个资料库显式绑定一个非空账号 UUID，防止把 A 账号的离线操作发到 B 账号。更换服务器且保留同一账号身份不必改变绑定；更换账号需在新资料库进行明确的数据迁移。该 UUID 不是访问凭据，也不是根密钥。

`pending_operations(profile,limit)` 返回按显式自增序列排列的不可变操作快照（不依赖可被 VACUUM 改写的隐式 rowid），每批 1–256 条。上传的是 operations.result 保存的当时版本，不能在发送时用已经继续编辑过的 records 最新值替换它。

## 持久化密文与确认

上传前可以显式调用 `coalesce_unstaged(profile, limit)`（1–4096）。在最早一批尚未暂存的操作中，同一记录只保留最后一次编辑为 pending；跨记录顺序沿用原 sequence，最终删除仍保留墓碑。SQLite IMMEDIATE 事务使它与新编辑/首次暂存互斥。只改变被替代操作的 pending 标记，不改/删业务记录、操作 request/result、已有密文请求或确认凭据，不推进 cursor；本地 revision 不回退。pending=0 只表示不再待发，服务器确认仍以 sync_uploads.ack_revision 为准。

**所有网络尝试前必须先 stage_upload。** 已暂存（含可能已经发出或已被服务器接受但丢响应）的操作完全排除在合并之外，即使同记录有更新版本，也先原样重试。暂存前读到的旧快照若已被合并，再 stage 会拒绝，调用方须重新读队列，不能直接发送旧快照。后台冲突请求不能借合并跳过。

此方法只处理有界窗口，是尽力合并，不保证一次遍历所有历史或消除与服务器相同的正文；没有删除操作历史、安全擦除或压缩备份。宿主/HTTP 尚未接入，现阶段不会自动运行合并或上传。100 次合成离线编辑可准备为 1 次待发的测试是状态证据，不是已测真实 Cloudflare 请求数。

调用方用 `zapime-crypto` 按账号、记录、操作、密钥版本和 kind 生成认证密文，构造与服务端 v1 一致的 UploadOperation，再调用 `stage_upload`。组件校验 ID、类型、删除标志、长度/字符形状及远端基修订，并要求上传当前队首操作；`sync_uploads` 仅保存密文上传请求。原有 `records` 和 `operations` 中的本地业务正文仍为明文；这不是整个 SQLite 数据库的静态加密。

第一次生成的完整请求被 SQLite 事务持久化。重启或丢失网络响应后重试返回同一份请求，包括 nonce 和密钥版本；不能对同一 operation_id 重新随机加密，否则服务器会按 operation_id_reused 拒绝。密钥轮换尚未实现，不能在存在待发请求时丢弃其旧密钥。

调用方必须验证服务端响应的账号、操作、内容与修订，再调用 `acknowledge_upload`。确认原子更新服务端实体修订、队列 pending 和确认凭据，不覆盖用户后续已经做出的本地修改。重复确认同一结果安全；不一致、未暂存或过期确认拒绝。暂存请求元数据与原操作快照不一致时拒绝发送/确认。

确认上传**不推进拉取游标**。本地记录 revision、服务端实体 revision 和账号拉取 cursor 是三个概念。其他设备可能已经在相邻游标写入操作，不能用自己的上传成功修订直接跳过它们。远端应用与 cursor 的原子推进将在后续同步客户端中实现；当前 cursor 保持 0，未提供会丢失远端记录的裸游标跳转接口。

## 验证与限制

测试覆盖重启后请求字节一致、继续编辑后旧上传确认不覆盖新版本、确认幂等/错误拒绝、跨账号与乱序拒绝、待发快照独立、旧 SQLite 迁移保留数据/队列、未知未来版本拒绝。形状占位密文仅用于状态测试，实际 AEAD 与服务端交换/恢复由独立服务灾备 CI 验证。

未实现：HTTP/TLS 传输、设备凭据与平台密钥托管、远端记录认证导入、冲突副本与解决、cursor 原子应用、恢复后向空服务重建队列、四端 UI。冲突目前不能自动跳过已暂存队首；失败时必须保留本地记录和暂存请求，不能静默丢弃。
