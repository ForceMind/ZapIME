# 离线智能润色：未接模型前的输出安全守卫

状态：**独立安全组件，未连接推理引擎、Android 语音 UI 或联网服务；不表示智能润色已可用**。
需求追踪 [#113](https://github.com/ForceMind/ZapIME/issues/113)。

## 用途

将来用户单独安装、同意使用设备内轻量模型后，推理线程可以把识别原文和模型候选传给
`VoicePolishSafety.inspect(original, rewritten)`。
检查结果只有固定的原因码（不包含原文），而
`VoicePolishSafety.safePreview(original, proposed)` 在任何不符合安全门禁时直接原样退回文本，
**绝不**触发写入编辑器/剪贴板/备份、网络或模型加载。

当前已合并的 `VoiceTextCleanup` 仍是仅规则的语气词及重复短句精简；新的守卫不是替代
识别器、不是语言模型，也不被现有双语音结果自动调用。

## 首个 fail-closed 检查集

- 非空、规范 Unicode（拒绝不成对代理项和控制符）、输入/输出 UTF-16 ≤2048，
  候选长度不超过原文的 1.5 倍且不少于 1/4。
- 不接受 `<think>`、ChatML 角色标记或 Markdown 三反引号等生成痕迹。
- 原文与候选的 **阿拉伯数字/小数/时间样式** 和**中文数字片段**必须严格同序一致；
  药品计量单位、金额货币符号和含年月日时分的完整单位也必须不变。
- 否定字符及英文 `not/no/never/cannot/don't` 等否定片段不得新增/删除/替换；
  引号内完整字符串、URL 和邮箱按出现顺序原样保留。
- 严格门禁不能证明姓名、因果、指代关系和语用含义等语义保真。
  它宁愿错误拒绝一些合法的书面语改写，也不自动放行明显变更事实的候选。
  模型结果的最终责任仍需使用者在**原文/保守精简/智能润色**的可逆预览中亲自确认。

## 工程和验收边界

纯 Java 类无 Android API、模型、JNI、音频、网络依赖。
`scripts/test_android_voice_polish_safety.py` 会编译/执行**实际产品 Java 文件**，
验证 20 个冻结合成用例（数字、药量、金额、否定、英文否定、URL/邮箱、引用、生成标签、超长和异常Unicode）。
此检查是离线守卫单测，不得替代未来真实 Qwen3.5/Qwen3 推理和手机质量测评。

下一个实际可用切片还需要：(1) 模型来源 revision/量化 SHA/许可固定与手动导入；
(2) 单独受限、可取消、不阻塞输入线程的 Android 本机推理 worker；
(3) 真实模型输出进入本守卫，并在**只读第三预览**里显示；
(4) 两个语音后端、API28/35/36 和三星 S25 真机上的数字、否定、人名、
语义误改、峰值内存/温度/电量/取消/锁屏/退出完整验收；
(5) 用户点击才经现有 `VoiceCommitTransaction` 提交一次。

当前不应把该代码或合成 PASS 写成模型精度、推理速度或稳定发布声明。
