# 源码发布流程

当前版本 `v0.1.0-alpha.1` 是源码预发布；成熟的仓库流程不代表四端产品已经稳定。二进制公开发行需另行完成许可、真机、签名及升级验收。

## 版本与输入

`.github/release-plan.json` 固定版本、源码范围及发布说明路径。发布整理使用独立分支和 PR；核对功能基线、完整来源与许可记录、STATUS、CHANGELOG、中英文首页及接管入口。保留失败，不将旧 CI、旧签名或旧 APK 赋予新源码身份。

`source-release.yml` 在 PR 做准备与检查；main 上计划文件变化会执行受控发布。发布任务单独使用 `contents: write`，不需要复制个人访问令牌。普通源码检查继续只读。源码发布检查不替代各平台系统输入或真机验收。

## 产物

准备脚本从精确 Git 提交生成根树源码归档、`metadata.json` 与 `SHA256SUMS`。元数据记录 commit、tree、固定子模块 Gitlink 和不包含子模块内容的限制。归档不递归读取子模块工作目录，不打包编译缓存、APK、模型权重或私钥。根仓库已有来源、锁文件及许可证仍保留。

完整构建使用 `git clone --branch <tag> --recurse-submodules https://github.com/ForceMind/ZapIME.git`。解压源码附件不能自动获得子模块内容，勿用无记录的上游最新源码补齐。

## 发布与复验

检查通过后固定本次 workflow 的 `github.sha`，先创建草稿预发布并上传校验附件，再公开。已有同名 tag 必须指向同一提交；已公开版本不能覆盖改写，修正另发版本。同源草稿可按脚本校验后补全。

发布后查询实际 Release/tag/附件，再下载源码包与校验文件核对摘要、元数据和提交身份。只有观察到公开 Release 才记录“已发布”；工作流失败保留现场，修复后使用同源安全重试或新版本，不强推标签。

`v0.1.0-alpha.1` 不附 APK/语音权重。开发包来源和独立验收见[候选试用](CANDIDATE_RANKING_TRYOUT.md)；公开通用二进制先处理[许可待办](LICENSE_AUDIT.md)、稳定签名和集中设备验收。
