# ZapIME 语音输入精简预览（V3 初始切片）

需求跟踪：[#113](https://github.com/ForceMind/ZapIME/issues/113)。这是 **Android 两个离线语音引擎（X-ASR 与 VoiceKey）共同使用**的识别结果后处理，独立于模型推理和麦克风。不是云端 API、大模型改写，也不宣称能理解所有口语语义。

## 交互与数据所有权

- 识别录音、流式临时文本、停止、最终识别、取消和 **用户确认后一次插入** 的现有路径不变。
- 语音设置里新增「默认预览精简版」开关；**默认关闭**。开启后，最终识别完成再计算本机精简版，预览它而不是直接上屏。关闭则先显示原文；无论设置如何，在确认前均可通过「查看识别原文 / 查看精简版」切换。
- 原始识别字符串在同一次语音会话内保留；当前明确选择的版本才送到已有 `VoiceCommitTransaction`。会话结束、取消、重新录音或切换输入框，原文和精简版都会被丢弃。**不单独写入个人资料库、日志、文件、服务器或统计**。
- 停止后的文本精简由固定的本机字符串逻辑完成。无云端联网，也不新增额外模型下载。
- 如果精简结果与原文相同，切换按钮显示「当前内容无需精简」并禁用；不能对原始文本作无意义转换。

## 刻意保守的 V1 规则

1. 只移除明确独立成段、且后面跟逗号的“嗯，”“呃，”“额，”“那个，”“就是说，”等口头填充词；“那个项目”“这个数据”不会被当作填充词。
2. 只去掉**相邻且完整相同**、长度不少于 6 个 Unicode 码点的重复中文短句，保留末次出现及其原标点；例如「我们先检查网络，我们先检查网络，然后重试。」成为「我们先检查网络，然后重试。」。
3. 数字与量词、否定和禁止词、引号、较短重复、无标点的重复以及英语独立句均原样保留。不会因为含“就是”三个字就删除后面的理由，也不生成新的词语或语序。
4. 超过 8192 UTF-16 字符或 128 个分隔段，以及计算异常时，原样返回识别结果；不得截断、写出中间态或让输入线程等待模型。
5. 任何情况下，用户都必须在本机预览后点击原有「确认插入」，同时保留编辑器身份、选择范围、权限、epoch 和取消的已有强验证。退出时不把文本同步到其他设备。

## Android 真实运行环境门禁（#116）

上游 #114 原测试只编译和执行共享 Java 算法的 JVM 主机用例；后续 #116 在现有签名测试 APK 的 `VoiceInstrumentation` 中增加真实 Android 产品类加载运行，并在 **X-ASR/native 和 VoiceKey 离线模型**两条路径中共用：

- 通过目标包的 `ClassLoader` 和反射执行当前安装 APK 的 `VoiceTextCleanup.concise`，不复制测试算法或用宿主回传伪数据。
- 逐例验证语气词、完全重复、否定、金额、模糊指代、emoji、英语及超长原文等保守处理。验证本机开关的关闭、开启、关闭三次状态和异常退出的 `finally` 恢复。
- 不唤起网络、麦克风、不往编辑器提交合成文字、不记录识别文本或真实用户内容。与既有 `VoiceCommitProbe` 的真实 Android `Editable`/一次提交测试分别验收，不合并为假定的真实语音拨测。
- Python 的 Android Native 和 VoiceKey 系统验收程序均要求明确的 `PASS installed Android offline voice cleanup and restored local opt-in preference` 标志；缺少/异常时不宣告该轮通过。
- 本门禁 **不能替代** 真正说话→ASR→语音栏实时开关→确认后一次上屏的用户路径，也不能替代三星 S25 设备质量验证；它只证明真实系统 Android 在两条后端准备路径确实执行了本机规则和设置逻辑。

## 不应该误称为已经实现的内容

- 真正基于上下文把长段口语改写为「简洁明了的书面语」、修正错词、自动补标点、精简逻辑结构，这些需要受授权限制的**离线小模型**和内容守恒测试；目前没有集成新的模型或远端 LLM。
- 对人名、数字、金额、否定、医学/法律等关键内容的语义保真需要独立人类评测。中文普通话、方言、英文混输与 60 秒自然录音都仍需要真实设备验收。
- JVM 上的真实 Java 规则用例只能验证确定性算法，不能代替 Android API28/35/36 系统键盘、离线双语音模型、真机和稳定签名验收。

可继续研究**本机轻量重写模型**作为下一代「智能精简」：模型必须能关闭、仅在停止后运行、不能直接写到编辑器、输出与原文逐项比对姓名/数值/否定，失败直接回退原文。任何云端方案需用户另行显式选择并获得清晰隐私提示；默认继续 local-first。
