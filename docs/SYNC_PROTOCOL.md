# 同步服务协议 v1（开发中）

独立服务实现于 `services/sync`，不是水杉云协议的兼容声明。四端客户端尚未接入，不以服务端测试替代四端同步验收。

## 身份与权限

管理员本地 CLI 创建账号 UUID 和首个 owner 设备。API 使用 `Authorization: Bearer <设备令牌>`，只接受请求头，不接受 URL 参数中的令牌。令牌由密码学随机源生成 32 字节，数据库仅保存 SHA-256，30 天到期；服务端管理权限可通过显式本地命令重发指定设备凭据。

owner 可以授权最多 32 个当前有效设备并撤销同账号设备；member 可同步和撤销自己，不能授权其他设备。每个事务在账号行锁后重新检查令牌摘要、到期、撤销与角色，避免中间件认证和撤销之间的竞态。凭据轮换同样使先前已认证但尚未进入事务的请求失效。

当前“授权设备”只分配服务访问凭据，不传递 E2EE 根密钥，也没有完成双设备核对码、配对或密钥轮换。不能把任意新设备 API 令牌称为已配对完成。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/healthz` | 数据库就绪、协议版本，无账号资料 |
| GET | `/v1/devices` | 本账号设备及授权状态，不含令牌/摘要 |
| POST | `/v1/devices` | owner 显式授权，正文仅 `name`；返回一次新令牌 |
| DELETE | `/v1/devices/{id}` | owner 撤销设备或 member 撤销自身 |
| POST | `/v1/changes` | 单条密文操作，幂等写入 |
| GET | `/v1/changes?after=0&limit=100` | 按账号单调修订拉取，不读其他账号 |

## 密文操作

请求 `Content-Type: application/json`；未知字段、追加 JSON、超过 100000 字节的请求、无效 UUID/版本/长度拒绝。账号和来源设备来自认证，不接受调用方传入账号以切换租户。

```json
{
  "operation_id": "每次操作稳定且非零的 UUID",
  "record_id": "实体 UUID",
  "key_id": "客户端密钥版本 UUID",
  "kind": 4,
  "base_revision": 0,
  "deleted": false,
  "envelope": {"version": 1, "nonce": "24 字节无填充 base64url", "ciphertext": "认证密文的无填充 base64url"}
}
```

kind：1 词库、2 候选规则、3 短语、4 收藏、5 剪贴板。现有实体不可悄悄改变 kind。外层 Envelope 与 `zapime-crypto` v1 完全一致：XChaCha20-Poly1305、24 字节 nonce、16–65552 字节密文。服务端只校验形状，无法验证 AEAD 标签或看见正文。

客户端必须使用 `zapime-crypto::Binding` 绑定账号(profile)、实体、操作、密钥版本和 kind，并在加密正文中包含完整记录和删除状态。拉取后先认证解密，再核对完整记录与外层 metadata；不得直接相信服务端提供的 `deleted`、kind 或文本类型。无法认证的条目应隔离并报错，不得上屏或覆盖本地数据。TLS 和 E2EE 分别解决传输与服务器不可读问题，不能互相替代。

成功返回 `{account_id,device_id,revision,operation}`。服务器 revision 是账号下的同步游标，与本地 SQLite 的实体 revision 不等价，客户端需要单独映射，不能直接覆盖原有本地修订。

## 幂等、冲突与删除

一次 PostgreSQL 事务持有账号行锁，完成授权复核、幂等检查、实体条件更新、不可变操作日志及全局游标递增。相同账号/设备/operation_id 的相同语义请求返回原结果；改变正文、密文、删除状态或来源设备的重放返回 `409 operation_id_reused`。JSON 空格和字段顺序不参与摘要，typed canonical operation 参与摘要。

`base_revision` 必须等于当前服务端实体修订；首次创建为 0。过期写入返回 `409 revision_conflict` 和当前密文记录；记录不存在时 current 为 null。服务端不按客户端时钟覆盖，不静默丢弃冲突版本；客户端应保留本地未同步内容并提供后续解决流程。

删除也是带认证密文的操作，保存 tombstone，不自动回收。旧设备拿着旧 revision 不能让已删除条目复活。显式恢复仍需基于当前 tombstone 修订形成新操作。收藏不受剪贴板容量/清理规则影响；当前服务尚未实现剪贴板独立保留期和容量策略，过期需客户端显式发删除操作。

每账号按保守双份编码大小计费，当前总额限制 256 MiB；达限整条操作回滚，重试不重复计费。不自动删除永久收藏或历史来腾空间；后续需要用户可见的配额和历史压缩/快照方案。

## 拉取、恢复与边界

拉取读取不可变操作流，limit 1–100，返回 changes、next_cursor、head。next_cursor 为最后返回操作修订，不能直接跳到 head；空页保持输入游标。请求 after 大于服务器 head 返回 `409 invalid_cursor`，避免恢复了较旧数据库后客户端静默误判已经同步。

数据库备份必须保留账号 ID、设备摘要、记录、操作与游标的一致快照。服务端重建且无法保留历史时，需要客户端主动重新导入恢复资料并建立新同步映射；该完整流程尚未实现。服务器不保存解密根密钥或恢复码，管理访问凭据不能替代客户端恢复材料。

API 默认仅回环监听，部署需 HTTPS。具备 100000 字节正文限制、固定 envelope 边界、32 个并行请求上限、数据库连接数/查询期限和通用错误；生产还需外层速率限制、防火墙、监控和安全审计。未声称已生产部署或通过第三方安全审计。

## 可选 R2/S3 对象存储（服务器 schema v2）

线上 v1 API 与客户端密文封装不变。设置 `ZAPIME_OBJECT_BACKEND=s3` 时，新 Change 正文保存在私有 S3/R2 的 `zapime/v1/<account>/<sha256>.json`，PostgreSQL 两张表仅保存 storage_version=2、account_id 和 sha256 引用。旧内联 Change 可继续读取；已有外置引用而没有对象配置时启动拒绝。旧服务端 schema v1 程序不能打开升级后的数据库。

只有通过事务内授权、重放、冲突和配额校验后才执行外部写入，使用 If-None-Match 条件创建。对象写成功再提交修订；事务失败可能留下无引用密文，不自动清理。重试从不可变操作记录还原原结果，不覆盖或重新生成正文。R2 的 HTTP/S3 错误不直接返回给客户端，也不在日志暴露签名或凭据。

读取最多八路并发，按修订恢复原顺序；缺失、过大、错误哈希、账号不匹配或不可用对象均使整页失败（503），不把它们当成空页或推进 next_cursor。哈希验证只校验云端对象完整性，仍不能替代客户端 AEAD 身份认证。服务健康入口只检查数据库；R2 真实写/读/删除检查由显式管理员 check-storage 完成，不把公共健康探针变成无限次 R2 写请求。

备份与新服务器/新对象桶恢复详见 SERVER_DEPLOY.md。每账号仍使用保守 256 MiB 记账；不代表 Cloudflare 免费额度上限或全账号账单保护。
