# 工具面板的物理入口验收

本切片只修独立Android验收宿主，不改产品。依据是完整Android运行42459746972/API36首轮的 `tools_open` 失败：空编辑器中，工具按钮触摸与 `RESET_NEW_CONFIGURATION` 重建重叠；驱动收到注入ACK，但产品没有记录 `tools_open`，真实面板仍为字母键盘。原始现场和精确源码先保存在[失败证据](evidence/tools-touch-stability-20261107/README.md)，不会因修复后成功而改写。

原入口使用泛型click：从一次Accessibility树读取坐标，紧接着发送DOWN和标成未来时间的UP；它没有实际持键时长，也没有等当前键盘几何稳定。现将工具重启测试的打开、返回，以及符号工具入口接到语音物理入口已有的 `stableImeTarget` / `touchImeOnce`。泛型click继续服务其他旧测试，本切片不把整个测试框架重写。

统一的物理边界：

1. 读取独立宿主的实际焦点、`InputMethodManager.isActive(normal)`和公开IME动画状态。API30+还要求公开root Insets报告IME可见；API28保留焦点、served editor和真实IME窗口/按钮几何条件，不声称它执行API30 Insets路径。
2. 仅选择真实IME窗口内可见Button，固定窗口与按钮几何。连续稳定窗口仍为原有300ms，不增加任意长sleep。额外比较公开Accessibility节点身份，避免配置重建后坐标相同却已换了一颗按钮。
3. 稳定后重取几何，触摸前再确认相同节点/窗口/边界；目标已换则明确失败，不自动重新点击。每次入口最多注入一组DOWN/UP，复用已有实际50ms持键。注入ACK仍不算面板打开。
4. 已打开的工具面板不再toggle；只有尚未打开时才触摸一次。随后必须在真实IME窗口同时看到“返回键盘”和“离线语音”，再经过相同稳定检查。返回字母页也验证真实IME内的字母按钮。

原 `tools_empty_editor_restart`、隐私选项重启、服务真实退出、完整独立Editable正文及语音慢IPC取消断言全部保留。本修复不会在测试失败时重发toggle，不改产品权限、设置策略、EditorInfo/选区准入、线程或候选模型，也不把改良驱动当作生产组字bug已修。

这些检查仍是有界采样；平台可以在检查后发生新配置变化，单次触摸仍可能被取消。遇到这种情况，原面板后置断言和失败现场继续使门禁失败，不能因ACK或后续成功把那次失败改成通过。

本地完整test-only宿主按官方API36r02/JDK17、Java8源目标编译通过；14项候选严格报告/上下文/设置恢复及8项CI设备/诊断隐私检查通过。它们不是新的模拟器物理入口结果。后续需按新精确源码回读完整Android API28/35/36、语音UI和真实服务退出结果；S25另行验收。
